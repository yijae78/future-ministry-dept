## 1. 무엇을 하는가

**교회학교 교사를 위한 자비스 스킬 3종 + 워크플로우 3본 명세를 한 리포에 묶은 패키지다. 코드가 아니라 「능력(스킬)」을 배포하는 리포이며, 실행 가능한 파이썬 워크플로우 1본(책→영상 변환기)이 함께 들어 있다.**

리포의 선언문은 README 첫머리에 그대로 박혀 있다 — "**AI가 신앙을 대신하지 않게 하는 AX.** 행사가 끝나면 흩어지는 교회가 아니라, 한 권의 책과 준비된 교사가 남는 교회." 이 한 문장이 패키지 전체의 설계 기준이다. AI는 교사의 성경연구를 대신하지 않고, 아이들의 문장을 고치지 않으며, 행사의 판단을 대신 내리지 않는다. AI가 하는 일은 **판을 깔고, 골격을 만들고, 손이 많이 가는 배관을 대신 도는 것**까지다.

리포 전체 파일은 6개뿐이다(실측 `git ls-files` 결과). `README.md`, 스킬 3본(`skills/church-event-director/SKILL.md`, `skills/grace-video-maker/SKILL.md`, `skills/pbs-teacher-spirituality/SKILL.md`), 워크플로우 명세 1본(`workflows/WORKFLOWS.md`), 실행 스크립트 1본(`workflows/book_to_video.py`). 무겁지 않다 — 대신 각 SKILL.md의 밀도가 높다.

### 1-1. 스킬 ① `pbs-teacher-spirituality` — 교사 영성모임 (152줄)

**대상**: 교회학교 교사들(대학생~장년). **트리거**: "교사 영성모임 / PBS 성경연구 / 교사 모임 준비 / 본문 연구 가이드 / 나눔 진행안".

스킬이 스스로 선언하는 존재 이유는 이것이다 — "성경연구의 목적은 **하나님을 알아가는 것**이다. 그리고 하나님 말씀대로 살아가기 위해 적용점을 정리해 내 삶에 적용하는 삶을 살려고 노력하는 태도를 갖는 것이다." 그리고 반(反)목적을 하나 함께 못 박는다 — "말씀연구의 지식으로 **사람을 평가하고 정죄하라고 하는 성경연구가 아니다.** 연구가 깊어질수록 칼끝은 언제나 남이 아니라 나를 향한다 — 적용 칸의 주어는 항상 '나'다." 한 줄 선언은 "**교사가 먼저 은혜받지 않으면 전달할 것이 없다.**"

불가침 윤리 5조가 모든 응답에 걸린다. ①AI는 신앙을 대신하지 않는다 — 본문을 요약해 주지 않고, 묵상의 결론을 대신 내리지 않으며, "이 본문의 의미는 ~입니다"라고 선언하지 않는다 ②사실 정보는 제공하되 불확실한 것은 지어내지 않는다, 해석 논쟁은 "여러 전통이 다르게 읽는다"고 밝히고 단정하지 않는다 ③특정 교단·신학 진영을 편들거나 깎아내리지 않는다 ④답을 내기 전에 스스로 한 번 반박한다 ⑤모르는 것은 모른다고 말한다.

산출물은 2종이다.

**산출물 ① 개인 연구 가이드(모임 전, 각 교사용)** — 연구 흐름은 확정 4단 `성경본문 → 관찰/해석 → 성경적 원리 → 적용`이다. **해석에서 바로 적용으로 건너뛰지 않고 「성경적 원리」를 문장으로 뽑는 단계가 사이에 있다** — 이것이 적용이 자의적 투사가 되는 것을 막는 장치다. 실물 PBS 노트에서 채록한 양식이 그대로 실려 있는데, 노트는 **펼침면**으로 쓴다(왼면 = 본문 표시 + 관찰/해석, 오른면 = 〈성경적 원리〉 칸 + 〈적용〉 칸). 원리는 "하나님의 인도와 때는 (우리와) 다르다"처럼 **시대를 넘어 참인 명제 문장**으로, 적용은 "~하지 말라 / ~부터 하라"처럼 **이번 주의 행동 문장**으로 번호를 매겨 쓴다. 안내 순서는 기도 한 줄 → 본문 통독 최소 2회(두 번째는 소리 내어, **AI가 본문을 붙여주지 않는다 — 성경을 직접 편다**) → 관찰/해석 → 성경적 원리 → 적용 → 궁금함 기록 6단이다.

장르별 관찰 갈림길도 실물 노트 2종에서 채록되어 있다. **서신서·논설**(예: 디모데전서)은 논리의 뼈대를 따라가 절 구간을 나누고 소제목을 단다(연결어 '그러므로·그러나'가 구간 경계 단서). **내러티브**(예: 창세기 16장)는 인물을 따라가며 ①인물들이 무엇을 왜 했는가 ②하나님이 어디서 어떻게 개입하시는가 ③이 장면에서 드러나는 하나님의 성품은 무엇인가를 묻는다 — "내러티브의 주제는 흔히 '○○하시는 하나님'으로 수렴한다."

**산출물 ② 나눔 모임 진행안(모임 당일, 인도자용)** — 전제는 "공통 본문을 각자 **미리 PBS 해오는 것**이 입장권"이며 "모임은 연구하는 자리가 아니라 연구해 온 것을 나누는 자리"(약 1시간)다. 구성은 4단 60분: **해석 나눔 — 궁금함부터(25분)** → **적용 나눔(20분)** → **삶 나눔(15분)** → **마무리 기도제목 나눔과 합심기도(10분, 생략 불가)**. 인도 원칙 중 핵심은 "질문이 먼저다 — 잘 깨달은 것부터 시작하면 질문이 묻힌다"와 "인도자가 정답을 선언하지 않는다", 그리고 "풀리지 않는 질문은 억지로 닫지 않고 숙제로 남긴다"이다.

그룹 적응 규칙(새신자 포함 그룹은 용어를 풀고 새신자가 먼저 말하게 하지 않는다 / 장년 교사회는 삶 나눔 비중 증가 / 대학부는 진로·관계 질문 1개 삽입)과 실패 패턴(본문 요약본 요청 거절, 설교문·공과 대필 범위 밖, 학생용 공과로 오용 금지)도 명시되어 있다. 모임 마지막 5분의 기록은 갓생북 시즌 프로젝트에 남겨 시즌 말에 **"우리 교사들의 영성일지"** 한 권(PDF)이 된다.

### 1-2. 스킬 ② `church-event-director` — 행사 디렉터 (96줄)

**대상**: 행사 디렉터(누구든 — "목사든 전도사든 평신도든 학생 리더든 이 스킬은 역할을 특정하지 않는다"). **트리거**: "성경학교 준비 / 수련회 기획 / 행사 순서지 / 조편성 / 수련회 공지문 / 안전 점검". 한 줄 선언은 "**행사가 끝나면 흩어지는 것이 아니라, 한 권의 책이 남는다.**"

입력은 한 줄이면 시작한다 — 예: "여름성경학교, 초등부 30명, 1박2일, 예산 80만원, 교사 6명". 받을 것은 ①행사 종류 ②대상·인원 ③기간 ④예산 ⑤교사·스태프 수 ⑥장소 ⑦(선택)주제 방향 ⑧갓생북 리더 지정 여부.

**산출물 7종**이 나온다.
1. **기획안(1쪽)** — 주제·목표(행사 후 아이들에게 남아야 할 것 한 문장)·콘셉트·프로그램 배치 이유
2. **타임테이블** — 표 형식 고정 `일자 | 시간 | 내용 | 장소`, **장소 열 생략 금지**. 실물 수련회 계획표에서 채록한 배치 원칙이 붙는다: "**이동은 프로그램이다**"(버스 탑승·출발·도착을 각각 별도 행으로 — 이동 시간을 안 잡는 것이 지연의 제1 원인), 등록·이름표 배부로 30분 배정해 연다, 여는 예배/닫는 예배로 여닫고 닫는 예배엔 작은 기도회를 붙인다, **식후에는 자유 → 대그룹 순서**(점심 직후 집중 프로그램 금지), 귀가 안내를 마지막 행으로. 그리고 ★핵심 — "**행사는 당일로 끝나지 않는다 — 다음 주일에 회수한다**"(다음 주일 예배에 시상식·축하를 얹고 공과도 행사 주제를 잇는다)
3. **역할 분담표** — 총괄·인솔·안전·찬양·레크·주방·구급·사진(갓생북 업로드 담당 겸). 교사 부족 시 겸임 우선순위 제시
4. **준비물·예산 체크리스트** — 품목별 수량·단가·담당자 칸, 초과 시 감액 우선순위
5. **조편성 도우미** — 새친구는 반드시 챙김이 옆에, 형제자매는 다른 조에, 조장 성향 균형
6. **안전 점검표 + 우천 플랜B ★생략 불가** — 출발 전(학부모 동의서·비상연락망·알레르기/지병·차량 보험·인솔자 대 인원 비율), 현장(위험구역·야간 인원점검 시각·구급함·병원 경로), 야외 프로그램별 실내 대체안
7. **공지문 3종** — 학부모 안내문(갓생북 링크 자리 포함)·학생 홍보문·주보 공지문. "**발송·게시는 반드시 사람이 한다 — 스킬은 초안까지만.**"

불가침 조항 4조 중 3항이 특히 강하다 — "**안전은 타협하지 않는다** — 인원 대비 교사 수·수상활동·야간이동·알레르기 확인은 사용자가 생략을 요청해도 점검표에서 빼지 않는다." 실패 패턴도 명시: 분 단위로 빽빽한 타임테이블 금지, 프로그램 수로 승부하지 않기, 새 프로그램을 행사 당일 처음 시도하지 않기.

### 1-3. 스킬 ③ `grace-video-maker` — 갓생북 회고 영상 (44줄)

**대상**: 리더·교사. **트리거**: "회고 영상 / 수련회 영상 만들어 / 갓생북 영상 / 행사 영상 / 책을 영상으로". 한 줄 정의는 "**책의 상영판.** 갓생북에 시간순으로 쌓인 사진과 글을 그 흐름 그대로 영상으로 옮긴다 — 책(PDF)은 각자 보는 것, 영상은 **함께 보는 것**."

만드는 순서 5단: ①**자료 정렬** — 업로드 시간순으로 나열, **순서를 창작하지 않는다** ②**구성 설계** — 여는 타이틀(행사명·날짜) → 시간순 장면들 → 닫는 카드. 글은 자막 또는 단독 타이틀 카드로 하되 "**아이들의 문장을 고치지 않는다(맞춤법도 그대로 — 그 서툰 문장이 기록의 진짜다)**". 장면당 3~5초, 3분 기준 약 40~55장 ③**렌더** — 로컬 ffmpeg로 조립(16:9 1080p), 렌더 명령과 로그를 남긴다 ④**검수** — 완성본을 처음부터 끝까지 확인 ⑤**전달** — 파일 위치와 상영 안내(빔프로젝터 비율·소리 체크).

불가침 조항 4조 중 3·4항이 실무상 결정적이다 — "**아이들 얼굴이 담긴 영상이다** — 외부 공개(유튜브 등) 업로드는 이 스킬의 범위 밖이며 '교회 내부 상영·학부모 링크 공유까지'가 기본"이고, "음악은 저작권 안전한 소스만(교회 보유 라이선스·로열티프리·자작). 임의의 대중가요를 쓰지 않는다."

활용 자리는 3곳이다 — **폐회식**에 짧은 1분 버전, **다음 주일** 예배·시상식에 본편 3분(행사 주일 회수 설계의 핵심 장면), **학부모 공유**는 갓생북 PDF 링크와 함께 교회 내부 채널로.

### 1-4. 워크플로우 3본 (`workflows/WORKFLOWS.md`)

"워크플로우 = 사건이 나면 저절로 도는 배관(스킬은 사람이 부를 때 일하는 능력). 전부 로컬 파이썬 — 구동 시 AI 사용료 0. 자비스 스케줄러(`cys schedule`) 또는 OS 스케줄러에 등록."

- **W1. 은혜 회수(grace-harvest)** — 최우선. 트리거: 주기(6h) + 행사 종료 신호. 갓생북 은혜(Supabase)의 새 기록·사진을 자비스 로컬 DB(`db/grace/`)로 복사·축적하고, 행사 종료 시 사진 원본을 로컬로 일괄 이관해 클라우드 용량을 비운다(**무료 티어 유지 장치**). 존재 이유: "'자비스=두뇌·로컬 DB' 원칙을 실제로 성립시키는 뼈대." **상태: 명세만 있음 — 구현 스크립트 미포함.**
- **W2. 책 마감(book-finalize)** — 트리거: 행사·시즌 종료. PDF 책 생성 확인 → 로컬 아카이브 → 회고 영상 생성(`grace-video-maker` 호출) → 책+영상+공유링크 패키지를 리더에게 전달. **핵심 부품인 `book_to_video.py`는 구현·검증 완료.**
- **W3. 기록→양육(record-to-nurture)** — 후속. 사람별 기록이 임계 분량에 도달하면 로컬 DB를 사람별로 누적("한 사람의 신앙의 책")하고 1:1 양육 대화 가이드 초안을 리더에게 제안. **상태: 명세만 있음.**

구현 순서는 W1(3주차) → W2(4주차) → W3(후속)로 로드맵에 잡혀 있다.

### 1-5. `workflows/book_to_video.py` — 유일한 실행 가능 스크립트 (129줄, 구현·검증 완료)

갓생북 프로젝트 폴더의 사진과 글을 **시간순 그대로** 1920×1080 슬라이드 영상으로 만든다. 로컬 실행(ffmpeg + Pillow)이라 AI·클라우드 비용 0이다. 스크립트가 자기 docstring에 박아 둔 원칙 2조 — "**순서를 창작하지 않는다 — 시간순(파일명순) 그대로**", "**아이들의 문장을 고치지 않는다 — 자막은 원문 그대로 싣는다**". 실제로 자막이 4줄을 넘치면 **자르지 않고 폰트 크기를 줄여서** 원문을 보존한다(84pt/54pt에서 시작해 30pt까지 6pt씩 감소).

### 1-6. v0.1 상태 고지 (README의 정직한 라벨)

README가 스스로 밝히는 미완 지점이다. ### 3-2. `book_to_video.py` 실행 전제 (스크립트 실측)

필요한 것은 두 가지다.

- **ffmpeg** — 스크립트가 `subprocess.run(["ffmpeg", ...])`로 직접 호출한다. PATH에 있어야 한다.
- **Pillow** — `from PIL import Image, ImageDraw, ImageFont`

설치·확인:

```bash
python -m pip install Pillow
ffmpeg -version      # 버전이 출력되면 PATH 등록 완료
python --version     # Path | None 타입 문법을 쓰므로 Python 3.10 이상 권장
```

Windows(PowerShell)에서 ffmpeg가 없다면:

```powershell
winget install --id Gyan.FFmpeg -e
python -m pip install Pillow
ffmpeg -version
```

**한글 폰트**: 스크립트의 `FONT_CANDIDATES`가 위에서부터 순서대로 시도한다.

```
C:\Windows\Fonts\malgunbd.ttf
C:\Windows\Fonts\malgun.ttf
/System/Library/Fonts/AppleSDGothicNeo.ttc
/usr/share/fonts/truetype/nanum/NanumGothicBold.ttf
```

하나도 없으면 스크립트가 `[경고] 한글 폰트를 찾지 못했다 — 자막이 깨질 수 있다. FONT_CANDIDATES에 경로를 추가하라.`를 출력하고 기본 폰트로 진행한다. Windows에서는 맑은 고딕이 기본 탑재라 보통 그대로 통과한다.

### 3-3. `book_to_video.py` 사용법 (스크립트 docstring 원문)

```
사용법:
  python book_to_video.py <프로젝트폴더> [--title "여름성경학교 2026"] [--out video.mp4]
                          [--music bgm.mp3] [--sec 4] [--closing "함께해 주셔서 감사합니다"]

프로젝트 폴더 규칙:
  - 사진: *.jpg *.jpeg *.png — 파일명 순으로 정렬(갓생북 내보내기가 시간순 이름을 쓰면 그대로 흐름이 된다)
  - 글(선택): 사진과 같은 이름의 .txt (예: 001.jpg + 001.txt) → 그 장면의 자막이 된다
  - captions.json(선택): {"001.jpg": "첫날 도착!", ...} 형식도 지원
원칙:
  - 순서를 창작하지 않는다 — 시간순(파일명순) 그대로.
  - 아이들의 문장을 고치지 않는다 — 자막은 원문 그대로 싣는다.
```

인자 기본값(실측 `argparse` 정의):

| 인자 | 기본값 | 설명 |
|---|---|---|
| `project` (위치인자) | 필수 | 사진·글이 든 프로젝트 폴더 |
| `--title` | `""`(없음) | 여는 타이틀 카드 문구. 비우면 타이틀 카드 생략 |
| `--out` | `recap_video.mp4` | 출력 파일 경로 |
| `--music` | `""`(없음) | BGM 파일. 지정 시 `-stream_loop -1`로 반복하고 끝에서 2초 페이드아웃 |
| `--sec` | `4.0` | 장면당 노출 초 |
| `--closing` | `함께해 주셔서 감사합니다` | 닫는 카드 문구 |

출력 사양(코드 실측): 해상도 `1920x1080`, 배경색 `(16,18,24)` 어두운 남색, 자막색 `(245,245,240)`, 프레임레이트 `30`, 코덱 `libx264` `-preset medium`, 픽셀포맷 `yuv420p`, 음악 지정 시 `aac` + `-shortest`. 자막 폰트는 타이틀 84pt / 일반 54pt에서 시작해 줄 수가 한계(타이틀 2줄 / 일반 4줄)를 넘으면 30pt까지 6pt씩 줄여 **원문을 자르지 않는다**. 사진 위 자막에는 하단 검은 띠가 깔린다.

**주의**: 프로젝트 폴더에 사진이 하나도 없으면 스크립트는 `[중단] <경로> 에 사진이 없다.`로 종료한다. ffmpeg 실패 시에는 `[실패] ffmpeg 오류:` 뒤에 stderr 마지막 1500자를 그대로 보여 준다. 정상 종료 시 `[완료] <out> — 장면 N개, 약 M초. 상영 전 처음부터 끝까지 재생 확인하라(검수는 사람 몫).`가 출력된다.

### 3-4. W1(은혜 회수) 설정 — 구현 전 고지

`workflows/WORKFLOWS.md` 원문: "**설정**: `config.example.json`의 SUPABASE_URL / SERVICE_KEY (각 교회 자비스 로컬에만 저장 — 저장소에 키 금지)".

★실측 고지 — **현재 커밋(`4c38cbe`)에는 `config.example.json`도 W1 구현 스크립트도 존재하지 않는다.** 리포 파일은 6개가 전부다. W1은 명세 단계이며, README도 이를 명시한다 — "W1(은혜 회수)은 명세만 실려 있다 — 각 교회의 Supabase 키가 필요해 설치 측에서 구성한다."

> ⚠ **보안 경고**: `SUPABASE_URL` / `SERVICE_KEY`는 **자리표시자다. 실제 값을 이 문서·저장소·커밋·로그·대화창 어디에도 적지 마라.** 리포 자체가 "저장소에 키 금지"를 규약으로 못 박고 있다. 키는 각 교회 자비스 로컬의 gitignore 대상 설정 파일 또는 OS 자격 증명 저장소에만 둔다. 특히 Supabase **service role key는 RLS를 우회하는 전권 키**이므로 절대 클라이언트·공개 저장소에 노출하지 않는다. 유출 의심 시 Supabase 대시보드에서 즉시 키를 회전(rotate)한다.

워크플로우를 주기 실행으로 등록할 때는 자비스 스케줄러를 쓴다(WORKFLOWS.md 지정 방식).

```bash
cys schedule add --id grace-harvest --in 6h --text "[W1] 은혜 회수 실행" --to master
```


완료 메시지 예: `[완료] .../recap_3min.mp4 — 장면 47개, 약 188초. 상영 전 처음부터 끝까지 재생 확인하라(검수는 사람 몫).`

**⑧ 검수 — 사람이 처음부터 끝까지 본다.** `grace-video-maker` 스킬의 검수 항목 그대로: 사진 누락 / 자막 오타(원문과 대조 — 아이 문장의 오타는 오타가 아니라 원문이다) / 음악 싱크 / 잘린 화면. 스킬 불가침 1항이 "완성 영상을 처음부터 끝까지 재생 확인한 결과로만 완료를 말한다"이므로 이 단계를 건너뛰지 않는다.

**⑨ 상영·공유** — 폐회식에 1분본, 다음 주일 시상식에 3분본을 튼다(빔프로젝터 16:9 비율·소리 사전 체크). 학부모에게는 갓생북 PDF 책 링크와 함께 **교회 내부 채널로만** 공유한다. **유튜브 등 외부 공개 업로드는 스킬 범위 밖이며, 판단은 교회(사람)의 몫이다.**

### 시나리오 B — "교사 영성모임 한 시즌을 연다"

**① 시즌 첫 모임 2주 전** — `pbs-teacher-spirituality` 스킬을 부른다.

```
교사 영성모임 준비. 본문 디모데전서 2장, 장년 교사회 12명(새신자 2명 포함),
모임 시간 90분. 이번 시즌 갓생북 리더는 박OO 집사.
```

스킬은 한 번에 하나씩 물어 부족한 입력을 채운 뒤 **산출물 ① 개인 연구 가이드**를 준다. 여기에는 본문을 요약해 주는 내용이 없다 — 대신 PBS 노트 펼침면 양식(왼면 본문+관찰/해석, 오른면 성경적 원리+적용)과 서신서 장르 관찰법(연결어로 절 구간 나누기, 구간별 소제목, 번호 메모)이 나온다.

**② 각 교사에게 가이드를 배포한다.** 입장권은 "미리 PBS 해오는 것"이다. 교사들은 성경을 직접 펴고 통독 2회(두 번째는 소리 내어) → 관찰/해석 → 성경적 원리(명제 문장) → 적용(이번 주 행동 문장, 번호) → 궁금함 기록 순으로 각자 연구해 온다.

**③ 모임 당일** — 스킬을 다시 불러 **산출물 ② 나눔 모임 진행안**을 받는다.

```
디모데전서 2장 나눔 모임 진행안. 장년 교사회, 새신자 2명 포함, 90분.
```

60분 골격(해석 나눔 25분 → 적용 나눔 20분 → 삶 나눔 15분 → 기도제목 나눔과 합심기도 10분)이 나오고, 90분이면 삶 나눔 비중이 늘어난다(장년 교사회 적응 규칙). 인도자는 "어려웠던 곳 없으셨어요?"로 열고 **정답을 선언하지 않는다.** 새신자가 먼저 말하게 하지 않는다. 풀리지 않은 질문은 숙제로 남긴다.

**④ 마무리 5분** — 오늘의 발견 한 줄을 갓생북 「교사 영성일지」 프로젝트에 남긴다(링크가 없으면 기록 노트로 대체). 이 기록이 시즌 내내 쌓여 시즌 말에 **"우리 교사들의 영성일지" PDF 한 권**이 된다.

**⑤ 시즌 말** — 시나리오 A의 ⑤~⑨와 동일한 방식으로 `book_to_video.py`를 돌려 교사 영성일지의 상영판을 만들 수도 있다.

```bash
python book_to_video.py "$HOME/Future-Ministry/예배교육부/grace-projects/2026-교사영성일지" \
  --title "2026 교사 영성일지" --sec 5 --closing "다음 시즌에도 함께" \
  --out "$HOME/Future-Ministry/예배교육부/grace-projects/2026-교사영성일지/teachers_recap.mp4"
```
